# Reels Downloader

인스타그램 릴스 / 틱톡 / 유튜브 쇼츠 등 다양한 플랫폼의 영상을 개인용으로 다운로드하는 셀프호스팅 웹앱입니다.
로그인/회원가입 페이지가 있고, 다운로드는 서버에서 [yt-dlp](https://github.com/yt-dlp/yt-dlp)로 처리합니다.

> ⚠️ 개인 소장 목적으로만 사용하세요. 저작권이 있는 콘텐츠의 재배포는 각 플랫폼 이용약관 및 관련 법령에 위배될 수 있습니다. 본 도구는 그런 용도로 제공되는 것이 아닙니다.

## 시놀로지 NAS(Container Manager)에 배포하는 방법

### 방법 A. Container Manager의 "프로젝트" 기능 사용 (추천)

1. 이 폴더 전체(`reels-downloader/`)를 NAS의 아무 공유폴더에 업로드합니다.
   예: `/volume1/docker/reels-downloader`
2. **Container Manager → 프로젝트 → 생성**을 클릭합니다.
3. 프로젝트 이름을 입력하고, 경로로 위에서 업로드한 폴더를 지정합니다.
4. 소스로 **docker-compose.yml 사용**을 선택하면 자동으로 인식됩니다.
5. `docker-compose.yml`에서 `JWT_SECRET` 값을 임의의 긴 랜덤 문자열로 바꿔주세요. (필수)
6. 빌드 및 실행하면 컨테이너가 생성되고 `3000` 포트로 서비스됩니다.
7. 브라우저에서 `http://[NAS IP]:3000` 접속 후 회원가입으로 계정을 하나 생성하세요.
8. 계정을 만든 뒤에는 `docker-compose.yml`의 `ALLOW_REGISTRATION`을 `false`로 바꾸고
   프로젝트를 재빌드해서, 다른 사람이 임의로 가입하지 못하도록 막는 것을 권장합니다.

### 방법 B. SSH로 직접 빌드

```bash
cd /volume1/docker/reels-downloader
docker compose build
docker compose up -d
```

### 데이터 위치

- `./data` : 사용자 계정 및 다운로드 기록이 저장되는 SQLite DB
- `./downloads` : 실제 다운로드된 영상 파일 (사용자 ID별 하위 폴더)

두 폴더 모두 볼륨으로 마운트되어 있어서, 컨테이너를 재생성해도 데이터는 유지됩니다.
NAS의 백업 작업(Hyper Backup 등)에 이 두 폴더를 포함시키면 안전합니다.

## 외부에서 접속하고 싶다면

시놀로지의 **리버스 프록시** 기능(제어판 → 로그인 포털 → 고급 → 리버스 프록시)을 사용해
`https://reels.내도메인.com` 같은 주소로 HTTPS를 적용하는 것을 추천합니다.
HTTPS로 서비스한다면 `docker-compose.yml`의 `COOKIE_SECURE`을 `true`로 바꿔주세요.

## 주요 기능

- 회원가입 / 로그인 (JWT 쿠키 기반, 비밀번호는 bcrypt로 해시 저장)
- **가장 먼저 가입한 계정이 자동으로 관리자가 됩니다.**
- URL 입력 → 서버가 yt-dlp로 메타데이터(제목/썸네일) 조회 후 다운로드
- **화질 선택**: 최고화질 / 1080p / 720p / 480p / 360p / 오디오만(mp3) 중 선택 가능
- **여러 링크 일괄 다운로드**: 줄바꿈으로 여러 URL을 한 번에 입력하면 순서대로 처리
- **검색/정렬**: 다운로드 목록을 제목으로 검색하고, 최신순/오래된순/이름순/용량순 정렬
- **인앱 재생 미리보기**: 완료된 항목의 재생(▶) 버튼을 누르면 다운로드 없이 바로 스트리밍 재생
- **계정(프로필) 전체 수집**: 상단 "계정 전체 수집" 탭에서 프로필/릴스 탭 URL을 넣으면 최근 N개(10~200개, 선택 가능)를 한 번에 큐에 담아 순차적으로 다운로드
- **인스타그램 계정 로그인 연결** (설정 페이지): 아이디/비밀번호를 암호화 저장해두고 자동 로그인 상태로 요청하여, 비공개 계정 조회나 대량 수집 시 차단을 줄여줌
- 사용자별 다운로드 목록, 진행 상태 표시(다운로드 중 / 완료 / 오류)
- 완료된 영상 다운로드(저장) / 삭제
- 계정별로 파일이 분리 저장되어 여러 명이 써도 서로의 파일이 섞이지 않음
- **관리자 페이지** (`/admin.html`, 상단 "관리자" 버튼): 전체 사용자 목록, 사용자별 다운로드 수 / 저장 용량, 전체 통계, 사용자 삭제(파일 포함)

### 관리자 안내

- 서비스를 처음 켜고 **가장 먼저 회원가입한 계정**이 자동으로 관리자 권한을 갖습니다.
- 이후 가입하는 계정은 일반 사용자입니다.
- 관리자 페이지는 관리자 계정으로 로그인했을 때만 상단 메뉴에 "관리자" 버튼이 보이고, 다른 계정으로는 접근이 차단됩니다.

## 로컬(개발용)에서 바로 실행하고 싶다면

Node.js 20+, `yt-dlp`, `ffmpeg`가 로컬에 설치되어 있어야 합니다.

```bash
cp .env.example .env
npm install
npm start
# http://localhost:3000
```

## 이미 사용 중이던 분들을 위한 업그레이드 안내

기존에 이미 컨테이너를 띄워서 쓰고 계셨다면, 파일만 새 버전으로 교체하고 **재빌드**하시면 됩니다.
`data/app.db`는 그대로 유지되고, 앱이 처음 켜질 때 자동으로 새 컬럼(관리자 권한, 화질 정보 등)을 추가합니다.
기존에 가입해서 쓰시던 계정 중 **가장 먼저 만든 계정이 자동으로 관리자로 승격**됩니다.

```bash
cd /volume1/docker/reels-downloader
docker compose down
# (여기서 새 파일들로 폴더 내용을 덮어쓰기)
docker compose build --no-cache
docker compose up -d
```

## 계정 전체 수집이 잘 안 될 때 (인스타그램 로그인 연결)

인스타그램은 로그인하지 않은 상태로 프로필을 여러 번 조회하면 금방 차단하거나 빈 목록을 돌려주는 경우가 많습니다.
상단 메뉴의 **"설정"** 페이지에서 두 가지 방법 중 하나(또는 둘 다)를 등록해두면 훨씬 안정적으로 동작합니다.
**둘 다 설정하지 않아도** 앱은 정상 동작하며, 이 경우 로그인 없이 공개 콘텐츠에 접근합니다.

### 방법 1. 아이디/비밀번호 로그인 — 2FA가 꺼진 계정용

- 설정 페이지에서 인스타그램 아이디/비밀번호를 입력하면 yt-dlp가 요청마다 자동으로 로그인합니다.
- 비밀번호는 서버 DB에 **암호화되어 저장**됩니다 (평문 저장 안 함).
- 로그인에 성공하면 세션을 사용자별로 캐시해뒀다가 재사용해서, 매번 새로 로그인하지 않습니다.
- **2단계 인증(2FA)이 켜진 계정은 이 방법으로 로그인할 수 없습니다.** 이 경우 방법 2를 사용하세요.

### 방법 2. 쿠키 파일 업로드 — 2단계 인증(2FA) 계정용 (권장)

브라우저에서 이미 2FA까지 마치고 로그인한 세션의 쿠키를 그대로 가져오는 방식이라, 2FA 여부와 상관없이 동작합니다.

1. 크롬/엣지에 **"Get cookies.txt LOCALLY"** 같은 확장 프로그램을 설치합니다.
2. 브라우저로 `instagram.com`에 로그인(2FA 포함)한 상태에서 확장 프로그램으로 쿠키를 `cookies.txt`로 내보냅니다.
3. 설정 페이지의 "방법 2" 항목에서 그 파일을 선택하거나, 내용을 복사해서 붙여넣고 저장합니다.
4. 쿠키가 설정되어 있으면 **방법 1보다 항상 우선 적용**됩니다.

> ⚠️ 쿠키에는 로그인 세션 정보가 들어있어 유출되면 계정이 도용될 수 있습니다. 본인만 접근 가능한 환경에서 사용하세요.
> 쿠키는 시간이 지나면 만료되므로, 갑자기 다시 안 되기 시작하면 쿠키를 새로 내보내 교체해주세요.

### 우선순위 정리

1. 설정 페이지에 업로드한 쿠키 파일이 있으면 그것을 사용
2. 없으면 아이디/비밀번호 로그인을 시도 (등록되어 있는 경우)
3. 둘 다 없으면 컨테이너 전체 공용 쿠키 파일(`INSTAGRAM_COOKIES_FILE` 환경변수, 있다면)을 사용
4. 그마저도 없으면 로그인 없이 진행

### CRED_ENC_KEY 설정 (권장)

`docker-compose.yml`의 `environment`에 아래처럼 추가하면, `JWT_SECRET`과 별개의 키로 비밀번호를 암호화합니다.

```yaml
    environment:
      - JWT_SECRET=please_change_this_to_a_long_random_string
      - CRED_ENC_KEY=another_long_random_string_for_credentials
```

> 이 값을 나중에 바꾸면 기존에 저장된 인스타그램 비밀번호를 복호화하지 못하게 되어, 설정 페이지에서 다시 로그인해줘야 합니다.

## 문제 해결

- **다운로드가 "오류"로 표시됨**: yt-dlp는 업데이트가 잦습니다. 컨테이너를 재빌드(`docker compose build --no-cache`)하면
  최신 yt-dlp로 갱신됩니다. 특정 사이트(특히 인스타그램)는 로그인 쿠키가 필요한 경우도 있어
  100% 모든 링크가 되는 것은 보장되지 않습니다.
- **로그인이 계속 풀림**: `JWT_SECRET`을 재빌드할 때마다 다르게 설정하면 안 됩니다. 한 번 고정하세요.
